확정
①정산상품 없음 — 요율은 회원(Node)이 아니라 관계(Edge)에 저장
②등록은 직속 상위 1명 + 관계 요율 세트만 입력

두 가지 배분 구조 — 폭포수 vs 병렬

확정

배분 구조는 두 가지가 병존한다. 어느 구조인지에 따라 참여자·용어·세무 판정이 전부 달라진다.[출처: 회의록 "8.14 원장/계약 구조" §1 — 결정 레지스터 M1]

폭포수 — 일반 파트너 체인
가맹점
└ 영업사원 (기록용)
　└ 영업조직 (기록용)
　　└ 파트너(하위)
　　　└ 파트너(상위) ← 최상위
　　　　└ 페이허그 (재양수)

채권 양수인은 맨 아래 파트너, 페이허그는 그 위에서 재양수한다. 상위에서 하위로 순차 하향 배분되므로 '최상위' 개념이 성립한다. 영업사원·영업조직은 기록용 — 실제 돈이 오가는 상대는 파트너뿐이다.

병렬 배분 — 직계약 (다우 등)
가맹점
└ 페이허그 (양수인)
　├ 다우데이타 (각각 배분)
　└ 투자자 (각각 배분·연결 시)

양수인이 곧 페이허그다. 전액을 받아 각 당사자에게 각각 배분한다 — 순차가 아니다. 이 트랙에서는 '파트너'·'최상위' 용어를 사용하지 않는다.

용어 규율 확정: '최상위'·'파트너'는 폭포수 전용 용어다. 병렬 배분(다우 직계약) 서술·화면에는 사용 금지 — 다우데이타의 위상이 최상위여도 '최상위'라 부르지 않는다.[출처: 회의록 §1 — M2 · 사용자 답변 P4]

매출/원가 귀속 원칙 확정

A사가 100만원을 수취하면 A사 매출 100만원. A사가 B사에 40만원을 지급하면 B사 매출 40만원 + A사 원가 40만원. 누가 직접 받았는지에 따라 매출 귀속이 달라지므로, 폭포수와 병렬은 참여자별 매출·원가가 다르게 잡힌다.[출처: 회의록 §2 — M3]

기록 vs 실제 지급 확정

  • 계약 흐름상 실체는 가맹점 ↔ 파트너 둘뿐 — 영업사원·영업조직은 기록용 참여자다.
  • 페이허그 관점에서는 실지급/기록을 구분할 필요 없이 전부 기록한다(계약 하기 나름).
  • 다우·영업조직은 자체 시스템이 없어 페이허그가 관리를 대행한다.

[출처: 회의록 §1·§4 — M7]

요율 세트 — 관계(Edge) 1건이 갖는 값

확정(구성)

관계 1건은 아래 세트를 갖는다. 세트 구성은 확정이며, % 요율의 실값은 전부 미확정(충돌 C1) — 화면·문서 어디서든 예시로만 쓴다.[출처: 사용자 결정 ① 2026-08-19 · 현행 코드 근거 app/settlement/policies/page.tsx:51~98]

항목형식규칙상태
채권매입 수수료율% 소수관계별 계약값. 실값은 어떤 값도 채택하지 않는다 — 표기는 전부 "(예시)"구성 확정 값 미결(C1)
시스템이용료율% 소수관계별 계약값. 실값 미확정 동일구성 확정 값 미결(C1)
이체수수료정액(원)전 건 300원 고정 — 거래처별로 다르지 않고, 원장에 실리지 않는다. 화면에서는 고정 표시(입력 불가)이며 달라지는 것은 부담 주체뿐확정(M9)
VAT 방식별도/포함 (요율별)계약 설정 나름 — 정답 없음. 계층별 계약에 따라 달라지며, 별도면 페이허그 쪽에서 떼서 지급확정(M5)
납부 주체가맹점/상위/하위 (시스템료·이체료 각각)'대납' 개념 포함 — 아래 대납 케이스구성 확정
수취 주체상위 수취/하위 수취 (시스템료·이체료 각각)관계별 토글구성 확정
이체수수료 대납 케이스 확정: 파트너 유인용으로 이체수수료를 대납하는 경우, 파트너가 받는 채권매입수수료 수익에서 페이허그가 300원을 차감 수취한다 — 시스템 이용료와 같은 방식.[출처: 회의록 §5 + 사용자 답변 2026-08-19 — M9]

면세/과세 판정 기준 확정

  • "계약서에 이름 없으면 무조건 과세." 면세 = 채권 양수인 → 재양수인 → 재재양수인 사슬에 등장하는 경우(채권의 대행).
  • 폭포수: 페이허그 = 재양수인 = 사슬 안 = 채권매입수수료 면세.
  • 직계약(다우): 페이허그가 양수인이고, 그 아래 배분받는 자(예: 다우 하위 영업조직·투자자)는 사슬 밖 = 과세(법인이라 VAT).

[출처: 회의록 §3 — M4]

단정 표기 재검토 확정(지정): "채권매입수수료 = 면세사업"이라는 단정 표기는 조건부(사슬 등장 여부에 따름)이므로 정책서에서 재검토 대상이다.[출처: 회의록 §3 — M6]
거래유형(카드/배달)별 요율 차등 미결: 카드/배달 요율이 다르게 계약된 실계약 존재 여부 확인 후, 관계 요율을 단일 세트 vs 유형별 2세트로 택일한다(§10 #1). 그 전까지 해당 화면에는 "확인 필요" 배지를 유지한다.

다우·제휴사 트랙 — 직계약(병렬 배분)

확정

다우데이타는 제휴사 유형 + 직계약(병렬 배분)이다. 채권매입·양도가 없고 수수료만 정산한다(별도 제휴 계약 — 언급되는 0.6%가량은 실값이 아닌 예시). 위상은 최상위이지만 병렬 트랙에서는 '최상위'·'파트너' 용어를 사용하지 않는다(§2 용어 규율).[출처: 사용자 답변 2026-08-19 P4 + 회의록 §1]

다우데이타

  • 기록 범위 확정: 페이허그의 공식 기록은 다우까지다. 다우 하위 영업조직(예스넷)은 다우 데이터/원장에 등장하지 않으며, 다우 이하 배분은 다우 소관이다.[출처: 회의록 §4 — M8]
  • 과세 확정: 직계약에서 페이허그 아래 배분받는 자는 채권 사슬 밖이므로 과세(법인 VAT)다 — §4 판정 기준.
호칭 주의: 회의 원문의 호칭은 정식 용어로 승격하지 않는다 — 공식 문서에는 "다우 하위 영업조직(예스넷)"으로 풀어 쓴다.
